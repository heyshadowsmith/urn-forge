# Regenerate the code after a manifest change

The generated files come from the manifest. After each change to the manifest, compile again and commit the generated files with the manifest. Gate 4 of `verify` fails if the committed files are not the same as a fresh compile.

## Before you start

- You have a project that compiles. Refer to [Set up a project](set-up-a-project).
- You changed `domain.manifest.yaml`. Any change counts, also a change to a `description`.
- If callers already use the manifest, compare it with the old version first. `urn-forge diff` shows if the change breaks a caller or a stored row. Refer to [Check compatibility in CI](check-compatibility).

::: warning
Do not edit the generated files. `compile` replaces them, and gate 4 fails until you do.
:::

## 1. Compile

Run this command from the project folder:

```bash
npx urn-forge compile
```

`compile` writes each file that changed, and shows the new fingerprint:

```
wrote      generated/domain.runtime.generated.ts
wrote      generated/domain.schemas.generated.ts
fingerprint sha256:b48297b4537c103460a0d8c21ae9ae155f0bd5b185c94813eb2a78c92b66c4bf
```

If a file did not change, `compile` shows `unchanged` and does not write it.

If the manifest has an error, `compile` writes no file. Correct the error first. Refer to [Diagnostics](../reference/diagnostics).

## 2. Read the header

Each generated file starts with the same two lines:

```ts
// @generated by urn-forge 0.1.0 — do not edit
// fingerprint: sha256:b48297b4537c103460a0d8c21ae9ae155f0bd5b185c94813eb2a78c92b66c4bf
```

The fingerprint is a SHA-256 hash of all that changes the generated code:

- the manifest, as the compiler reads it
- the plugins, their versions and their configuration
- the version of urn-forge
- the primitives, the constraints and the kinds of urn-forge

The same inputs always give the same fingerprint and the same files. Thus:

- If two files have different fingerprints, they come from different compiles. Compile again.
- If you update urn-forge, the fingerprint can change with no manifest change. Compile again and commit the result.

For more, read [Determinism and the fingerprint](../explanation/determinism).

## 3. Update the core and the scenarios

Run this command:

```bash
npx urn-forge verify
```

A manifest change can make gate 1 or gate 3 fail. For example:

- A new operation needs a handler and a tagged feature. Refer to [Add an operation](add-an-operation).
- A new required input field needs a column in each input table. Refer to [Add a field](add-a-field).

To find the cause of each failure, refer to [Fix a gate that fails](fix-a-failing-gate).

## 4. Commit the generated files

Commit the manifest and the generated files in the same commit. Then the files in the repository always agree with the manifest.

## Fix drift

Gate 4 compiles the manifest into a temporary folder. Then it compares each file, byte for byte, with the committed file.

If you change the manifest but do not compile, gate 4 fails:

```
gate 4  drift         FAIL  2 generated file(s) compared byte for byte against generated
    generated/domain.runtime.generated.ts:2:1  error  generated-differs  differs from a fresh compile (hand-edited or stale); run `urn-forge compile`
    generated/domain.schemas.generated.ts:2:1  error  generated-differs  differs from a fresh compile (hand-edited or stale); run `urn-forge compile`
verify failed: gate 4
```

The location gives the first line that is different:

- **Line 1 or line 2** is the header. The file comes from a different compile, so it is stale.
- **A later line** with the same header means that a person edited the file. For example, a line added at the end of the runtime gives this error:

  ```
      generated/domain.runtime.generated.ts:265:1  error  generated-differs  differs from a fresh compile (hand-edited or stale); run `urn-forge compile`
  ```

If a generated file has no source in the current compile, gate 4 also fails:

```
    generated/old.generated.ts  error  generated-orphan  generated file has no source in the current compile; run `urn-forge compile`, which removes it
```

To fix drift, do these steps:

1. Run `npx urn-forge compile`. It also removes the generated files that it no longer makes.
2. Run `npx urn-forge verify`, and make sure that gate 4 passes.
3. Commit the generated files, and the removal of the old files.

If you want a change in the generated code, change the manifest or the configuration, not the file.

## Result

`npx urn-forge compile` shows `unchanged` for each file:

```
unchanged  generated/domain.runtime.generated.ts
unchanged  generated/domain.schemas.generated.ts
fingerprint sha256:b48297b4537c103460a0d8c21ae9ae155f0bd5b185c94813eb2a78c92b66c4bf
```

Gate 4 passes:

```
gate 4  drift         PASS  2 generated file(s) compared byte for byte against generated
```
