# The generated schemas

The Valibot plugin (`valibot`, version 0.1.0) writes the file `domain.schemas.generated.ts` in the `--out` directory. The file has one Valibot schema and two types for each field, entity, event and error of the manifest that is not sunset. It also has one rule function for each invariant. Operations have no declarations in this file. This page gives the form of each part of the file. For the reasons for the brands, refer to [The functional core and brands](../explanation/functional-core).

## The file

| Item | Value |
| --- | --- |
| File name | `domain.schemas.generated.ts` |
| Plugin | `valibot`, version `0.1.0`. The plugin accepts only the configuration `{}` |
| Import | `import * as v from 'valibot';` |
| Imported by | The generated runtime file, as `./domain.schemas.generated.js`. Refer to [The generated runtime](./generated-runtime) |
| Text format | UTF-8 with no byte order mark, `\n` line endings, and one `\n` at the end of the file |

Do not edit this file. Gate 4 compares it, byte for byte, with a new compile. Refer to [Verification gates](./verification-gates).

## The header

Each generated file starts with the same two lines. The `compile` engine adds them, not the plugin. In `schema.generated.sql`, the two lines start with `--` in place of `//`. Refer to [The Postgres schema](./postgres-schema):

```ts
// @generated by urn-forge 0.1.0 — do not edit
// fingerprint: sha256:492eef5cf4429536322062da365f080ff6cc4091bb6ae5563c713a73570b3b10
```

| Line | Form | Description |
| --- | --- | --- |
| 1 | `// @generated by urn-forge <version> — do not edit` | The version of urn-forge that made the file |
| 2 | `// fingerprint: sha256:<64 hexadecimal digits>` | The SHA-256 hash of the canonical JSON of the compile inputs. All the generated files of one compile have the same fingerprint, and `compile` shows it on its last line |

An empty line follows the header. The fingerprint is a hash of these inputs:

- The canonical IR of the manifest.
- The name and configuration of each plugin, in the sequence of the plugin list.
- The urn-forge version.
- The name and version of each plugin.
- The primitives with their constraint names, and the kinds, that urn-forge knows.

For the reasons for the fingerprint, refer to [Determinism and the fingerprint](../explanation/determinism).

## The sequence of the declarations

| Position | Content | Present |
| --- | --- | --- |
| 1 | The header and an empty line | Always |
| 2 | `import * as v from 'valibot';` | Always |
| 3 | `// Helpers`, then the helper functions that the fields and the rules use | Only if a field is a `decimal`, a `date` or a `timestamp` |
| 4 | `// Fields`, then one declaration for each field | Always. The comment is there also if the manifest has no fields |
| 5 | `// Entities`, then one declaration for each entity. The rule functions of the invariants of an entity are part of its declaration | Always. The comment is there also if the manifest has no entities |
| 6 | `// Events`, then one declaration for each event | Only if the manifest has one or more events |
| 7 | `// Errors`, then one declaration for each error | Only if the manifest has one or more errors |

In the groups of fields, entities, events and errors, the declarations are in URN sequence. The sort compares UTF-16 code units, not the rules of a locale. There is one exception: an entity comes after each entity that it embeds, because its schema uses their schemas. In the insurance domain, `coverage` thus comes before `policy`. An empty line comes between two declarations. The properties of an entity, an event or an error are in the sequence of its `fields` list in the manifest.

## Helpers

The schemas of `decimal`, `date` and `timestamp` fields call helper functions. The rule functions of invariants also call them. The file has a helper only if a field or a rule uses it. The helpers are not exported.

| Helper | Declarations | Present if the manifest has |
| --- | --- | --- |
| Decimal | `DECIMAL` (a regular expression), `decimalFraction`, `decimalScaled`, `compareDecimal` | A `decimal` field |
| Decimal arithmetic | `unscaledDecimal`, `addDecimal`, `subtractDecimal`. They call the decimal helper | A rule with `+` or `-` on `decimal` values |
| Date | `isCalendarDate` | A `date` field or a `timestamp` field |
| Timestamp | `isUtcTimestamp`. It calls `isCalendarDate` | A `timestamp` field |

The helpers are always in the sequence of the table. Each helper is fixed text, so the generated bytes do not change with the TypeScript version. `compareDecimal` compares two decimal strings exactly, with `bigint`. No binary float holds the value. `addDecimal` and `subtractDecimal` also calculate exactly. The result has the larger number of digits after the point of the two values.

## Field schemas

Each field becomes one `v.pipe`:

```ts
/** <field URN> — <description> */
export const <Brand>Schema = v.pipe(
  <base actions>,
  <one action for each constraint>,
  v.brand("<field URN>"),
);
```

- The comment has ` — <description>` only if the field has a `description`.
- The base actions come first. Then each constraint becomes one action, in the sequence of the table of constraints, not in the sequence of the manifest.
- `v.brand("<field URN>")` is always the last action. The URN is a string literal in double quotes.

### Base actions

| Primitive | Base actions | Value type |
| --- | --- | --- |
| `boolean` | `v.boolean()` | `boolean` |
| `date` | `v.string()`, `v.check(isCalendarDate, 'Invalid date: Expected a calendar day YYYY-MM-DD')` | `string` |
| `decimal` | `v.string()`, `v.regex(DECIMAL, 'Invalid decimal: Expected digits with an optional fraction, such as 12.50')` | `string` |
| `enum` | None. The `v.picklist` of `values` is the first action | The union of the `values` as string literals |
| `float` | `v.number()`, `v.finite()` | `number` |
| `integer` | `v.number()`, `v.safeInteger()` | `number` |
| `string` | `v.string()` | `string` |
| `timestamp` | `v.string()`, `v.check(isUtcTimestamp, 'Invalid timestamp: Expected YYYY-MM-DDTHH:MM:SSZ in UTC, with up to 3 fraction digits')` | `string` |

### Constraint actions

| Primitive | Constraint | Action | Notes |
| --- | --- | --- | --- |
| `boolean` | `mustBe` | `v.value(<true or false>)` | The type stays `boolean` |
| `date` | `min` | `v.minValue("<day>")` | A date in the form `YYYY-MM-DD` sorts as text, so the text comparison is the date comparison |
| `date` | `max` | `v.maxValue("<day>")` | |
| `decimal` | `min` | `v.check((value) => !DECIMAL.test(value) \|\| compareDecimal(value, "<n>") >= 0, "Invalid value: Expected >=<n>")` | The check runs only on a value of the correct form. Thus a value that is not a decimal gets one issue, not two |
| `decimal` | `max` | The same check with `<= 0` and the message `Expected <=<n>` | |
| `decimal` | `exclusiveMin` | The same check with `> 0` and the message `Expected ><n>` | |
| `decimal` | `exclusiveMax` | The same check with `< 0` and the message `Expected <<n>` | |
| `decimal` | `scale` | `v.check((value) => !DECIMAL.test(value) \|\| decimalFraction(value) <= <n>, "Invalid decimal: Expected at most <n> digit(s) after the point")` | |
| `decimal` | `notIn` | `v.check((value) => !DECIMAL.test(value) \|\| ![<values>].some((excluded) => compareDecimal(value, excluded) === 0), "Invalid value: Expected none of <values>")` | `"13"` and `"13.00"` are the same value |
| `enum` | `values` | `v.picklist([<values>])` | Each value is a string literal in double quotes, in the sequence of the manifest. The output type is the union of the values |
| `float` | `min` | `v.minValue(<n>)` | The value is a number literal. `-0` stays `-0` |
| `float` | `max` | `v.maxValue(<n>)` | |
| `float` | `exclusiveMin` | `v.gtValue(<n>)` | |
| `float` | `exclusiveMax` | `v.ltValue(<n>)` | |
| `float` | `notIn` | `v.notValues([<values>])` | The values are number literals, in the sequence of the manifest |
| `integer` | `min` | `v.minValue(<n>)` | |
| `integer` | `max` | `v.maxValue(<n>)` | |
| `integer` | `multipleOf` | `v.multipleOf(<n>)` | |
| `integer` | `notIn` | `v.notValues([<values>])` | |
| `string` | `minLength` | ``v.check((value) => [...value].length >= <n>, (issue) => `Invalid length: Expected >=<n> but received …`)`` | The length is in Unicode code points, not UTF-16 code units. The message is the message of `v.minLength` |
| `string` | `maxLength` | The same, with `<=` | |
| `string` | `regex` | `v.regex(/^(?:<pattern>)$/u)` | The pattern must match the whole value. The `u` flag is set. A `/` in the pattern becomes `\/` |
| `string` | `format` | `v.uuid()`, `v.email()` or `v.url()` | For `uuid`, `email` and `uri` |
| `timestamp` | `min` | `v.check((value) => !isUtcTimestamp(value) \|\| Date.parse(value) >= Date.parse("<t>"), "Invalid value: Expected >=<t>")` | The values compare as instants, so `09:00:00Z` and `09:00:00.000Z` are equal |
| `timestamp` | `max` | The same check with `<=` and the message `Expected <=<t>` | |
| `timestamp` | `exclusiveMin` | The same check with `>` and the message `Expected ><t>` | |
| `timestamp` | `exclusiveMax` | The same check with `<` and the message `Expected <<t>` | |

The constraint actions of one field are in the sequence of the rows for its primitive in this table.

Examples from the primitives test fixture:

```ts
/** urn:demo:kinds:value:field:quantity */
export const ValueQuantitySchema = v.pipe(
  v.number(),
  v.safeInteger(),
  v.minValue(1),
  v.maxValue(99),
  v.notValues([13]),
  v.brand("urn:demo:kinds:value:field:quantity"),
);

/** urn:demo:kinds:value:field:price */
export const ValuePriceSchema = v.pipe(
  v.string(),
  v.regex(DECIMAL, 'Invalid decimal: Expected digits with an optional fraction, such as 12.50'),
  v.check((value) => !DECIMAL.test(value) || compareDecimal(value, "0.01") >= 0, "Invalid value: Expected >=0.01"),
  v.check((value) => !DECIMAL.test(value) || compareDecimal(value, "9999.99") <= 0, "Invalid value: Expected <=9999.99"),
  v.check((value) => !DECIMAL.test(value) || decimalFraction(value) <= 2, "Invalid decimal: Expected at most 2 digit(s) after the point"),
  v.check((value) => !DECIMAL.test(value) || !["13.00"].some((excluded) => compareDecimal(value, excluded) === 0), "Invalid value: Expected none of 13.00"),
  v.brand("urn:demo:kinds:value:field:price"),
);
```

For the constraints themselves, refer to [Primitives and constraints](./primitives).

## Entity schemas

Each entity becomes one `v.object`:

```ts
/** <entity URN> — <description> */
export const <Brand>Schema = v.object({
  <property>: <Field brand>Schema,
  <property>: v.optional(<Field brand>Schema),
});
```

| Item | Rule |
| --- | --- |
| Property name | The `as` of the reference. If there is no `as`, the identifier of the target, which is the last segment of its URN. For example, `urn:demo:shop:order:field:unit_cost` becomes `unit_cost` |
| Property value | The schema of the target. Refer to the table that follows |
| `required: false` | The plugin puts the field schema in `v.optional(…)`. The key can then be absent, or its value can be `undefined` |
| `many` | The property holds a list. Refer to [List properties](#list-properties) |
| Sequence | The sequence of the `fields` list of the entity in the manifest |
| Unknown keys | `v.object` accepts a key that is not a property, and removes it from the parsed output |

```ts
/** urn:demo:shop:order:entity:line_total — The cost of one line */
export const OrderLineTotalSchema = v.object({
  total: OrderTotalSchema,
});
```

The property value comes from the form of the reference:

| Reference | Property value | Parsed type of the property |
| --- | --- | --- |
| `ref: <field>` | `<Field brand>Schema`, the schema of the field | The branded type of the field |
| `ref: <entity>` | `<Entity brand>Schema`, the schema of the embedded entity, with its invariants | The parsed type of the entity |
| `link: <entity>` | `<Key field brand>Schema`, the schema of the `key` field of the linked entity | The branded type of the key field |

In the insurance domain, `holder` is a link to `customer`, whose key is `customer_id`. `coverages` is a list of the embedded entity `coverage`:

```ts
  holder: CustomerCustomerIdSchema,
  coverages: v.pipe(v.array(PolicyCoverageSchema), v.minLength(1), v.maxLength(3), v.check((list) => new Set(list.map((item) => item.peril)).size === list.length, 'Invalid items: Expected no peril more than once')),
```

A link has the brand of the key field. Thus `tsc` accepts a `customer_id` of a customer as the value of `holder`, and refuses an identifier of a different entity. The schema does not make sure that the customer exists.

### Entities with invariants

If one or more invariants name the entity in `on`, the entity has a different form. The object goes into a constant that is not exported. One rule function for each invariant follows. Then the schema adds a check for each rule:

```ts
const <Brand>Fields = v.object({
  <property>: <Field brand>Schema,
});
/** <invariant URN> — <description>: <canonical rule> */
export const <Invariant brand>Rule = (p: v.InferOutput<typeof <Brand>Fields>): boolean =>
  <rule as TypeScript>;
/** <entity URN> — <description> */
export const <Brand>Schema = v.pipe(
  <Brand>Fields,
  v.forward(v.check(<Invariant brand>Rule, "<message>"), ["<first field of the rule>"]),
);
```

| Item | Rule |
| --- | --- |
| `<Brand>Fields` | The `v.object` of the entity, with the same properties as an entity without invariants. It is not exported, and it has no comment |
| `<Invariant brand>Rule` | One exported function for each invariant, in URN order. It gets the parsed object and returns `true` if the rule holds. For the TypeScript of each element of a rule, refer to [The rule language](./rule-language) |
| The comment of a rule | The URN and the `description` of the invariant, then the canonical text of the rule |
| `v.check` | Calls the rule function. The message is the `message` of the invariant, as a string literal in double quotes |
| `v.forward` | Puts the issue on the `reportOn` property of the invariant. Without `reportOn`, on the first field that the rule names, in the sequence of the rule text. For `deductible is absent or deductible < premium`, this is `deductible` |
| The sequence of the checks | URN order of the invariants |

The checks of the invariants run only if each property of the object is valid. If a field schema refuses a value, the payload gets only the issues of the fields. If the fields are valid, each invariant runs, and each rule that does not hold gives one issue.

An embedded entity keeps its invariants, because its property value is its schema. They run inside each embedded object, and the issue has the nested path, for example `coverages.1.limit`.

The `policy` entity of the insurance domain has two invariants:

```ts
const PolicyPolicyFields = v.object({
  policy_id: PolicyPolicyIdSchema,
  holder: CustomerCustomerIdSchema,
  coverages: v.pipe(v.array(PolicyCoverageSchema), v.minLength(1), v.maxLength(3), v.check((list) => new Set(list.map((item) => item.peril)).size === list.length, 'Invalid items: Expected no peril more than once')),
  effective_date: PolicyEffectiveDateSchema,
  expiry_date: PolicyExpiryDateSchema,
  premium: PolicyPremiumSchema,
  deductible: v.optional(PolicyDeductibleSchema),
});
/** urn:acme:insurance:policy:invariant:deductible_below_premium — A deductible, when there is one, is less than the premium: deductible is absent or deductible < premium */
export const PolicyDeductibleBelowPremiumRule = (p: v.InferOutput<typeof PolicyPolicyFields>): boolean =>
  (p.deductible === undefined || compareDecimal((p.deductible as string), (p.premium as string)) < 0);
/** urn:acme:insurance:policy:invariant:term_at_most_a_year — A policy lasts one year at most, also in a leap year: expiry_date - effective_date <= 366 */
export const PolicyTermAtMostAYearRule = (p: v.InferOutput<typeof PolicyPolicyFields>): boolean =>
  (epochDay((p.expiry_date as string)) - epochDay((p.effective_date as string))) <= 366;
/** urn:acme:insurance:policy:invariant:term_is_positive — A policy ends after it starts: expiry_date > effective_date */
export const PolicyTermIsPositiveRule = (p: v.InferOutput<typeof PolicyPolicyFields>): boolean =>
  (p.expiry_date as string) > (p.effective_date as string);
/** urn:acme:insurance:policy:entity:policy — An issued insurance policy */
export const PolicyPolicySchema = v.pipe(
  PolicyPolicyFields,
  v.forward(v.check(PolicyDeductibleBelowPremiumRule, "The deductible must be less than the premium"), ["deductible"]),
  v.forward(v.check(PolicyTermAtMostAYearRule, "A policy can last 366 days at most"), ["expiry_date"]),
  v.forward(v.check(PolicyTermIsPositiveRule, "The expiry date must be after the effective date"), ["expiry_date"]),
);
```

These issues come from a real parse with `PolicyPolicySchema`. Each payload has a valid `policy_id`, `holder` and `coverages`, `effective_date: '2026-06-01'` and `premium: '120.00'`:

| `expiry_date` | `deductible` | Issues, as path and message |
| --- | --- | --- |
| `2026-05-31` | Absent | `expiry_date`: `The expiry date must be after the effective date` |
| `2026-05-31` | `200.00` | `deductible`: `The deductible must be less than the premium`, then `expiry_date`: `The expiry date must be after the effective date` |
| `2026-12-31` | `200.00` | `deductible`: `The deductible must be less than the premium` |

With `premium: '0'` and `expiry_date: '2026-05-31'`, the only issue is `premium`: `Invalid value: Expected >0`. The field schema refused the premium, so the invariants did not run.

These issues come from a real parse with different `coverages`. Each payload is otherwise valid, with `effective_date: '2026-01-01'` and `expiry_date: '2026-12-31'`:

| `coverages` | Issues, as path and message |
| --- | --- |
| `[{ peril: 'fire', limit: '0' }]` | `coverages.0.limit`: `The limit of a coverage must be more than 0` |
| `[{ peril: 'fire', limit: '1' }, { peril: 'flood', limit: '0' }]` | `coverages.1.limit`: `The limit of a coverage must be more than 0` |
| `[{ peril: 'fire', limit: '1' }, { peril: 'fire', limit: '2' }]` | `coverages`: `Invalid items: Expected no peril more than once` |
| `[{ peril: 'hail', limit: '1' }]` | `coverages.0.peril`: `Invalid type: Expected ("fire" \| "flood" \| "theft") but received "hail"` |
| `[]` | `coverages`: `Invalid length: Expected >=1 but received 0` |

### List properties

If the reference has `many`, the property value is a `v.array` of the schema of one value: the field schema, the key field schema of a link, or the schema of an embedded entity. `v.optional(…)` goes around the list, not around each item.

| `many` | Property value |
| --- | --- |
| `true` | `v.array(<Field brand>Schema)` |
| `{ minItems: <n> }` | `v.pipe(v.array(<Field brand>Schema), v.minLength(<n>))` |
| `{ maxItems: <n> }` | `v.pipe(v.array(<Field brand>Schema), v.maxLength(<n>))` |
| `{ unique: true }` | `v.pipe(v.array(<Field brand>Schema), v.check((list) => new Set(list).size === list.length, 'Invalid items: Expected no value more than once'))` |
| `{ unique: true }` on a list of an embedded entity | `v.pipe(v.array(<Entity brand>Schema), v.check((list) => new Set(list.map((item) => item.<key>)).size === list.length, 'Invalid items: Expected no <key> more than once'))`. `<key>` is the property name of the `key` field of the entity |

If `many` has more than one key, the actions are in the sequence `minItems`, `maxItems`, `unique`. `unique` compares the values with `===`, as they come in. Thus the `decimal` values `"1.10"` and `"1.1"` are two different values. On a list of embedded objects, `unique` compares only the key of each object.

```ts
/** urn:demo:kinds:value:entity:lists — Lists of field values */
export const ValueListsSchema = v.object({
  sku: v.array(ValueSkuSchema),
  size: v.pipe(v.array(ValueSizeSchema), v.minLength(1), v.maxLength(3), v.check((list) => new Set(list).size === list.length, 'Invalid items: Expected no value more than once')),
  price: v.optional(v.pipe(v.array(ValuePriceSchema), v.maxLength(2))),
});
```

## Error schemas

Each error becomes one `v.object`. Its first property is `kind`. Then the properties of the error follow, with the same rules as for an entity. An error property can also be a link or an embedded entity:

```ts
/** <error URN> — <description> */
export const <Brand>Schema = v.object({
  kind: v.literal("<error URN>"),
  <property>: <Field brand>Schema,
});
```

- The type of `kind` is the URN of the error as a string literal, not `string`.
- An error with no fields has only the `kind` property.
- No property of an error can have the name `kind`. Pass 3 gives `reserved-property`. Refer to [Diagnostics](./diagnostics).
- The `category`, `retryable` and `message` of the error are not in this file. They are in `DispatchMap` in the runtime file.

```ts
/** urn:demo:shop:order:error:price_unavailable — No price is known for the item */
export const OrderPriceUnavailableSchema = v.object({
  kind: v.literal("urn:demo:shop:order:error:price_unavailable"),
  sku: OrderSkuSchema,
});
```

## Event schemas

Each event becomes one `v.object`, with the same form as an error schema. Its first property is `kind`, a literal of the event URN. Then the properties of the event follow, with the same rules as for an entity:

```ts
/** <event URN> — <description> */
export const <Brand>Schema = v.object({
  kind: v.literal("<event URN>"),
  <property>: <Field brand>Schema,
});
```

- The type of `kind` is the URN of the event as a string literal. A consumer can switch on it, as on the `kind` of an error.
- An event with no fields has only the `kind` property.
- No property of an event can have the name `kind`. Pass 3 gives `reserved-property`.
- The file has a schema for each event that is not sunset, also for an event that no operation emits.

From the insurance domain:

```ts
/** urn:acme:insurance:policy:event:policy_issued — A policy was issued */
export const PolicyPolicyIssuedSchema = v.object({
  kind: v.literal("urn:acme:insurance:policy:event:policy_issued"),
  policy_id: PolicyPolicyIdSchema,
  holder: CustomerCustomerIdSchema,
  premium: PolicyPremiumSchema,
});
```

The link `holder` uses the schema of the key field of the customer, as in an entity.

## The three exports of each atom

Each field, entity, event and error has three exports. An invariant has one export, its rule function `<Brand>Rule`. Each name starts with the brand identifier of the atom: the PascalCase form of its context and its identifier. For the rules of the names, refer to [URNs and names](./naming).

```ts
export const <Brand>Schema = …;
export type <Brand> = v.InferOutput<typeof <Brand>Schema>;
export type <Brand>Input = v.InferInput<typeof <Brand>Schema>;
```

| Export | Kind | Description | Example for `order.field.delivery` |
| --- | --- | --- | --- |
| `<Brand>Schema` | Constant | The Valibot schema | `OrderDeliverySchema` |
| `<Brand>` | Type | The parsed type. A field type has the brand. An entity, event or error type has a branded type for each property | `OrderDelivery`: one of the three `values`, with the brand `v.Brand<"urn:demo:shop:order:field:delivery">` |
| `<Brand>Input` | Type | The type that the schema accepts, with no brand | `OrderDeliveryInput`, which is `"standard" \| "express" \| "click & collect"` |

Only a parse with the schema can make a value of a branded type. If two atoms make the same export name, compile fails with `export-collision`. The name `<Brand>Rule` of an invariant is part of this check.

## Operations

An operation has no declaration in this file. Its `input` and `output` are entities, its errors are errors and its events are events, so their schemas are already in the file. The runtime file uses these schemas. Refer to [The generated runtime](./generated-runtime).

## Deprecated and sunset atoms

The plugin reads the live IR. The `status` of an atom changes the file in this way:

| `status` | Declarations | Comment |
| --- | --- | --- |
| `active` | All | `/** <URN> — <description> */`, on one line |
| `deprecated` | All, the same as for an active atom | Three lines or more, with an `@deprecated` tag. The tag gives `Superseded by <URN>` and `sunset on <date>`, if the atom has them |
| `sunset` | None. No schema, no type and no rule function | — |

The deprecated comment has this form:

```ts
/**
 * <URN> — <description>
 * @deprecated Superseded by <URN>; sunset on <date>.
 */
```

The tag is on the comment of a field, an entity, the rule function of an invariant, an event and an error. Editors cross out the name of each use of a deprecated export. `tsc` does not fail. From the insurance domain:

```ts
/**
 * urn:acme:insurance:policy:field:note — Free text about a coverage
 * @deprecated Superseded by urn:acme:insurance:policy:field:remark; sunset on 2027-06-30.
 */
export const PolicyNoteSchema = v.pipe(
  v.string(),
  v.brand("urn:acme:insurance:policy:field:note"),
);
```

The file depends on `status` only, never on `sunsetDate` and the reference date. For the lifecycle keys, refer to [The manifest](./manifest).
