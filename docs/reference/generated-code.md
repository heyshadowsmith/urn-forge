# Generated code

`urn-forge compile` writes these files in the `--out` directory. Do not edit them: gate 4 compares them, byte for byte, with a new compile.

| File | Plugin | Contents |
| --- | --- | --- |
| `domain.schemas.generated.ts` | `valibot` | A Valibot schema and two types for each field, entity, event and error. A rule function for each invariant |
| `domain.runtime.generated.ts` | `fcis` (needs `valibot`) | `Result`, `ok`, `emit`, `fail`, the handler types, `DomainCoreImplementation`, `DispatchMap` and `executeOperation` |
| `schema.generated.sql`, `domain.store.generated.ts` | `postgres` | Refer to [The Postgres schema](./postgres-schema) |

A sunset atom makes no code. The files are UTF-8, with `\n` line endings.

## The header

Each file starts with two lines and an empty line. In the SQL file, the lines start with `--`.

```ts
// @generated by urn-forge 0.1.0 — do not edit
// fingerprint: sha256:e69e1912890b626f5d271fdf69961f88eb5848e7928186ab788ce9f150ec1002
```

The fingerprint is a SHA-256 hash of the canonical IR, the plugin list and configurations, the urn-forge version, the plugin versions, and the known primitives and kinds. All files of one compile have the same fingerprint.

## Names

### URNs

```
urn:<namespace>:<domain>:<context>:<kind>:<identifier>
urn:demo:shop:order:field:unit_cost
```

| Segment | Source | Pattern |
| --- | --- | --- |
| `namespace` | `manifest.namespace` | `^[a-z][a-z0-9_]{0,62}$` |
| `domain` | `manifest.domain` | `^[a-z][a-z0-9_]{0,62}$` |
| `context` | The first segment of the short key | `^[a-z][a-z0-9_]{0,62}$` |
| `kind` | The second segment | `field`, `entity`, `invariant`, `operation`, `event` or `error` |
| `identifier` | The third segment | `^[a-z][a-z0-9_]{0,62}$` |

The short key `order.field.unit_cost` becomes `urn:demo:shop:order:field:unit_cost`. The manifest uses short keys. Feature tags, steps and generated code use URNs.

### Brand identifiers

The brand identifier is the PascalCase form of the context and the identifier. urn-forge joins them with `_`, splits at each `_`, removes empty parts, and makes the first letter of each part uppercase.

| Context | Identifier | Brand identifier |
| --- | --- | --- |
| `order` | `unit_cost` | `OrderUnitCost` |
| `geo_metry` | `radius` | `GeoMetryRadius` |
| `geo` | `metry_radius` | `GeoMetryRadius` |
| `a` | `b__c` | `ABC` |

Two atoms cannot have the same brand identifier, also if their kinds differ (`duplicate-brand`).

### Property names

A field reference makes a property. Its name is the `as` of the reference, else the identifier of the target. A `link: customer.entity.customer` with `as: holder` makes `holder`. The property names are the table headers in features, the names in rules, and the names in object cells.

The payload of each error and event has the property `kind`, with the URN of the atom. No other property of an error or event can have the name `kind` (`reserved-property`).

### Export names

`<Brand>` is the brand identifier.

| Kind | File | Export | Example |
| --- | --- | --- | --- |
| `field`, `entity`, `event`, `error` | Schemas | `<Brand>Schema`: the Valibot schema | `OrderQuantitySchema` |
| `field`, `entity`, `event`, `error` | Schemas | `<Brand>`: the parsed type, with brands (`v.InferOutput`) | `OrderQuantity` |
| `field`, `entity`, `event`, `error` | Schemas | `<Brand>Input`: the accepted type, with no brands (`v.InferInput`) | `OrderQuantityInput` |
| `invariant` | Schemas | `<Brand>Rule`: the rule function | `PolicyTermIsPositiveRule` |
| `operation` | Runtime | `<Brand>Handler`: the handler type | `OrderPriceLineHandler` |
| `entity` in `tables` | Store | `insert<Brand>`, `replace<Brand>`, `delete<Brand>` | `insertPolicyPolicy` |

If two atoms make the same export name, the compile fails with `export-collision`.

## The schemas file

### Sequence

1. The header, then `import * as v from 'valibot';`.
2. `// Helpers`: helper functions, only if a field is a `decimal`, `date` or `timestamp`. They are not exported.
3. `// Fields`, then each field.
4. `// Entities`, then each entity, with the rule functions of its invariants. An entity comes after the entities that it embeds.
5. `// Events`, then each event, if there are events.
6. `// Errors`, then each error, if there are errors.

In each group, the declarations are in URN order. Properties are in the sequence of the `fields` list.

### Fields

Each field is one `v.pipe`: the base actions, one action for each constraint, then `v.brand("<field URN>")`.

| Primitive | Base actions |
| --- | --- |
| `boolean` | `v.boolean()` |
| `date` | `v.string()`, `v.check(isCalendarDate, …)` |
| `decimal` | `v.string()`, `v.regex(DECIMAL, …)` |
| `enum` | `v.picklist([<values>])` |
| `float` | `v.number()`, `v.finite()` |
| `integer` | `v.number()`, `v.safeInteger()` |
| `string` | `v.string()` |
| `timestamp` | `v.string()`, `v.check(isUtcTimestamp, …)` |

| Primitive | Constraint | Action |
| --- | --- | --- |
| `boolean` | `mustBe` | `v.value(<true or false>)` |
| `date` | `min`, `max` | `v.minValue("<day>")`, `v.maxValue("<day>")` |
| `decimal` | `min`, `max`, `exclusiveMin`, `exclusiveMax`, `notIn` | `v.check(…)` with `compareDecimal`, an exact comparison |
| `decimal` | `scale` | `v.check(…)` with `decimalFraction` |
| `float`, `integer` | `min`, `max` | `v.minValue(<n>)`, `v.maxValue(<n>)` |
| `float` | `exclusiveMin`, `exclusiveMax` | `v.gtValue(<n>)`, `v.ltValue(<n>)` |
| `float`, `integer` | `notIn` | `v.notValues([<values>])` |
| `integer` | `multipleOf` | `v.multipleOf(<n>)` |
| `string` | `minLength`, `maxLength` | `v.check(…)` that counts Unicode code points |
| `string` | `regex` | `v.regex(/^(?:<pattern>)$/u)` |
| `string` | `format` | `v.uuid()`, `v.email()` or `v.url()` |
| `timestamp` | `min`, `max`, `exclusiveMin`, `exclusiveMax` | `v.check(…)` that compares instants |

```ts
export const ValueQuantitySchema = v.pipe(
  v.number(),
  v.safeInteger(),
  v.minValue(1),
  v.maxValue(99),
  v.notValues([13]),
  v.brand("urn:demo:kinds:value:field:quantity"),
);
export type ValueQuantity = v.InferOutput<typeof ValueQuantitySchema>;
export type ValueQuantityInput = v.InferInput<typeof ValueQuantitySchema>;
```

### Entities

Each entity is one `v.object`. `v.object` removes unknown keys from the parsed output.

| Reference | Property value |
| --- | --- |
| `ref: <field>` | The field schema |
| `ref: <entity>` | The entity schema, with its invariants |
| `link: <entity>` | The schema of the `key` field of the linked entity |
| `required: false` | `v.optional(…)` around the value |
| `many: true` | `v.array(…)` |
| `many: { minItems, maxItems, unique }` | `v.pipe(v.array(…), v.minLength(<n>), v.maxLength(<n>), v.check(…))`. On a list of embedded entities, `unique` compares the key |

If invariants name the entity in `on`, the object goes into a constant `<Brand>Fields` that is not exported. Each invariant adds an exported rule function and a `v.check`. `v.forward` puts the issue on the `reportOn` property, else on the first field of the rule. The checks run only if each property is valid.

```ts
const PolicyPolicyFields = v.object({
  policy_id: PolicyPolicyIdSchema,
  holder: CustomerCustomerIdSchema,
  coverages: v.pipe(v.array(PolicyCoverageSchema), v.minLength(1), v.maxLength(3), v.check((list) => new Set(list.map((item) => item.peril)).size === list.length, 'Invalid items: Expected no peril more than once')),
  effective_date: PolicyEffectiveDateSchema,
  expiry_date: PolicyExpiryDateSchema,
  premium: PolicyPremiumSchema,
  deductible: v.optional(PolicyDeductibleSchema),
});
/** urn:acme:insurance:policy:invariant:deductible_below_premium — A deductible, when there is one, is less than the premium: deductible is absent or deductible < premium */
export const PolicyDeductibleBelowPremiumRule = (p: v.InferOutput<typeof PolicyPolicyFields>): boolean =>
  (p.deductible === undefined || compareDecimal((p.deductible as string), (p.premium as string)) < 0);
/** urn:acme:insurance:policy:invariant:term_at_most_a_year — A policy lasts one year at most, also in a leap year: expiry_date - effective_date <= 366 */
export const PolicyTermAtMostAYearRule = (p: v.InferOutput<typeof PolicyPolicyFields>): boolean =>
  (epochDay((p.expiry_date as string)) - epochDay((p.effective_date as string))) <= 366;
/** urn:acme:insurance:policy:invariant:term_is_positive — A policy ends after it starts: expiry_date > effective_date */
export const PolicyTermIsPositiveRule = (p: v.InferOutput<typeof PolicyPolicyFields>): boolean =>
  (p.expiry_date as string) > (p.effective_date as string);
/** urn:acme:insurance:policy:entity:policy — An issued insurance policy */
export const PolicyPolicySchema = v.pipe(
  PolicyPolicyFields,
  v.forward(v.check(PolicyDeductibleBelowPremiumRule, "The deductible must be less than the premium"), ["deductible"]),
  v.forward(v.check(PolicyTermAtMostAYearRule, "A policy can last 366 days at most"), ["expiry_date"]),
  v.forward(v.check(PolicyTermIsPositiveRule, "The expiry date must be after the effective date"), ["expiry_date"]),
);
```

### Events and errors

Each event and error is one `v.object`. Its first property is `kind: v.literal("<URN>")`. The other properties follow the rules of an entity. The `category`, `retryable` and `message` of an error are in `DispatchMap`.

```ts
/** urn:acme:insurance:policy:event:policy_issued — A policy was issued */
export const PolicyPolicyIssuedSchema = v.object({
  kind: v.literal("urn:acme:insurance:policy:event:policy_issued"),
  policy_id: PolicyPolicyIdSchema,
  holder: CustomerCustomerIdSchema,
  premium: PolicyPremiumSchema,
});
```

### Deprecated atoms

A deprecated atom gets all its declarations. Its comment has an `@deprecated` tag, so editors cross out each use:

```ts
/**
 * urn:acme:insurance:policy:field:note — Free text about a coverage
 * @deprecated Superseded by urn:acme:insurance:policy:field:remark; sunset on 2027-06-30.
 */
```

## The runtime file

The runtime file imports the schemas file as `s`.

### Results

| Export | Type or signature |
| --- | --- |
| `ErrorPayloads` | One property for each error: `'<error URN>': s.<Brand>Input` |
| `EventPayloads` | One property for each event: `'<event URN>': s.<Brand>Input` |
| `Success<T, V = never>` | `{ ok: true; value: T; events: readonly V[] }` |
| `Failure<E>` | `{ ok: false; error: E }` |
| `Result<T, E, V = never>` | `Success<T, V> \| Failure<E>` |
| `ErrorUrn`, `EventUrn` | `keyof ErrorPayloads`, `keyof EventPayloads` |
| `ErrorFields<K>`, `EventFields<K>` | The payload without `kind` |
| `ok(value, events = [])` | Returns `{ ok: true, value, events }` |
| `emit(kind, fields?)` | Returns `{ ...fields, kind }`. `fields` is optional only if the event has no required fields |
| `fail(kind, fields?)` | Returns `{ ok: false, error: { ...fields, kind } }` |

`ok`, `emit` and `fail` do not parse. `executeOperation` parses.

### Handler types

```ts
/** <operation URN> — <description> */
export type <Operation brand>Handler = (
  input: s.<Input entity brand>,
) => Result<s.<Output entity brand>Input, <error types>[, <event types>]>;
```

For an operation with `changes`, the handler has a second parameter, `current: s.<Entity brand>`: the stored record, parsed and branded.

The input is parsed and branded. The output, the errors and the events are plain. The error type is the union of the declared errors, or `never`. The event type is the union of the events in `emits`. A handler is synchronous.

```ts
/** urn:demo:shipping:quote:operation:quote_shipping — Calculate the price to send a parcel */
export type QuoteQuoteShippingHandler = (
  input: s.ParcelParcel,
) => Result<s.QuoteQuoteInput, s.QuoteTooHeavyForExpressInput>;
```

`DomainCoreImplementation` has one property for each operation: `'<operation URN>': <Brand>Handler`. Declare the core with `satisfies DomainCoreImplementation`.

### `DispatchMap`

`DispatchMap` is a constant, `as const`, with one `OperationContract` for each operation URN.

| Type | Properties |
| --- | --- |
| `OperationContract` | `input`, `output`: `EntityContract`. `errors`: `ErrorContract` by error URN. `events`: `EntityContract` by event URN. `changes?`: `ChangeContract` |
| `ChangeContract` | `entity`: `EntityContract` with `urn`. `property` (the state), `from`, `to?`, `otherwise`, `key?`, `answer` (the output is the changed record). Only in a domain with `changes` |
| `EntityContract` | `schema`. `fields`: `PropertyInfo` by property name. `invariants?`: `InvariantInfo[]`, also those of embedded entities |
| `ErrorContract` | `EntityContract`, and `category`, `retryable`, `message: MessagePart[]`, `recordAs?` |
| `FieldInfo` | `urn` (for a link, the key field), `primitive`, `required`, `many?: true`, `link?` (the linked entity) |
| `EmbeddedInfo` | `entity`, `required`, `many?: true`, `fields` |
| `PropertyInfo` | `FieldInfo \| EmbeddedInfo`. Only an `EmbeddedInfo` has `entity` |
| `InvariantInfo` | `urn`, `rule` |
| `ErrorCategory` | `'validation' \| 'conflict' \| 'not_found' \| 'forbidden' \| 'precondition'` |
| `MessagePart` | `{ text: string } \| { field: string }` |

### `executeOperation`

```ts
export function executeOperation<U extends OperationUrn>(
  urn: U,
  rawPayload: unknown,
  core: DomainCoreImplementation,
): ExecuteResult<U>;
export function executeOperation(urn: string, rawPayload: unknown, core: DomainCoreImplementation): ExecuteResult;
```

In a domain with `changes`, `executeOperation` has a fourth parameter, `options?: ExecuteOptions`, with `current`: the record that the operation changes, as the shell loaded it.

| `ok` | `kind` | Other properties | Meaning |
| --- | --- | --- | --- |
| `true` | None | `urn`, `output`, `events` | Success. `output` and each event `{ urn, fields }` are parsed and branded |
| `false` | `'DomainError'` | `urn`, `error` | The handler returned a declared error |
| `false` | `'UnknownOperation'` | `urn`, `issues` | The URN is not an operation |
| `false` | `'InputRejected'` | `urn`, `issues` | The input schema refused the payload, also for an input invariant |
| `false` | `'ContractViolation'` | `urn`, `issues` | The core broke its contract. This is a bug in the core |

`DomainError<U>` has `urn`, `category`, `retryable`, `message` (with the field values), `fields`, and `record` if the error has `recordAs`. `EmittedEvent<U>` has `urn` and `fields`. Both are unions, so a `switch` on `urn` gives the correct `fields`.

`BoundaryIssue` has `path` (for example `coverages.1.limit`, or `''` for the payload), `fieldUrn?`, `invariantUrn?` and `message`.

`executeOperation` does these steps, and stops at the first failure:

| Step | Failure |
| --- | --- |
| 1. Find the URN in `DispatchMap` | `UnknownOperation`: `unknown operation <urn>` |
| 2. Parse the payload with the input schema | `InputRejected`. The handler is not called |
| 3. Find `core[urn]` | `ContractViolation`: `no handler for <urn>` |
| 3a. With `changes`: parse `current`, and examine its state | `ContractViolation` on `current`: `<urn> changes a record of <entity>: pass it as { current }`, or the parse issues. A state outside `from`: the `otherwise` error, filled from the record and the input, without a call of the handler |
| 4. Call the handler | `ContractViolation`: `the handler for <urn> did not return a Result; return ok(…) or fail(…)` |
| 5. For a failure: find the error in `errors`, parse it, and parse its `recordAs` event | `ContractViolation`: `<urn> failed with <kind>, which it does not declare`, or the parse issues. Else `DomainError` |
| 6. For a success: parse the output, then each event | `ContractViolation`: the parse issues, `the handler for <urn> returned events that are not a list`, or `<urn> emitted <kind>, which it does not emit` |
| 6a. With `changes`, when the output is the changed record: examine its state and key | `ContractViolation`: `the handler for <urn> answered <state property> "<value>", but the operation moves to "<to>"` (or `the state stays`), or `… answered <key> "<value>", but the record has "<value>"` |

`executeOperation` does not catch an exception from the handler, and does not make sure that a link points at an object that exists.

```ts
executeOperation(U, { weight_grams: 6000, zone: 'domestic', express: true }, core)
// {"ok":false,"kind":"DomainError","urn":"urn:demo:shipping:quote:operation:quote_shipping","error":{"urn":"urn:demo:shipping:quote:error:too_heavy_for_express","category":"precondition","retryable":false,"message":"An express parcel can weigh 5000 grams at most, not 6000","fields":{"kind":"urn:demo:shipping:quote:error:too_heavy_for_express","weight_grams":6000}}}
```
