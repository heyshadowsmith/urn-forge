# The generated runtime

The FCIS plugin (`fcis`, version 0.2.0) writes the file `domain.runtime.generated.ts` in the `--out` directory. The file has the `Result` type, the handler type of each operation, the registry `DomainCoreImplementation`, the contracts in `DispatchMap`, and the gatekeeper `executeOperation`. This page gives each export, its signature and its behavior. For the reasons for this design, refer to [The functional core and brands](../explanation/functional-core) and [Results and declared errors](../explanation/results-and-errors).

## The file

| Item | Value |
| --- | --- |
| File name | `domain.runtime.generated.ts` |
| Plugin | `fcis`, version `0.2.0`. The plugin accepts only the configuration `{}` |
| Necessary plugin | `valibot`. If it is not in the plugin list, compile fails with `missing-plugin` |
| Imports | `import * as v from 'valibot';` and `import * as s from './domain.schemas.generated.js';` |
| Header | The same two lines as the schema file. Refer to [The generated schemas](./generated-schemas) |

Do not edit this file. Gate 4 compares it, byte for byte, with a new compile.

## The sequence of the file

The file has five sections. Each section starts with a comment. Some parts are the same for each manifest (fixed). The other parts come from the manifest (generated).

| Section | Comment | Exports | Fixed or generated |
| --- | --- | --- | --- |
| Results | `// Results` | `ErrorPayloads` | Generated |
| | | `Success`, `Failure`, `Result`, `ErrorUrn`, `ErrorFields`, `ok`, `fail` | Fixed |
| Handler contracts | `// Handler contracts: branded input in; plain output or a plain declared error out (the shell brands both).` | One `<Brand>Handler` type for each operation | Generated |
| Registry | `// Registry` | `DomainCoreImplementation` | Generated |
| Dispatch | `// Dispatch` | `FieldInfo`, `EmbeddedInfo`, `PropertyInfo`, `InvariantInfo`, `EntityContract`, `ErrorCategory`, `MessagePart`, `ErrorContract`, `OperationContract` | Fixed |
| | | `DispatchMap` | Generated |
| Shell gatekeeper | `// Shell gatekeeper` | `OperationUrn`, `BoundaryIssue`, `DomainError`, `ExecuteResult`, `executeOperation` | Fixed |

The operations are in URN sequence, and the errors in `ErrorPayloads` are in URN sequence. The sort compares UTF-16 code units. The errors of one operation are in the sequence of its `errors` list in the manifest.

## Results

### `ErrorPayloads`

```ts
export interface ErrorPayloads {
  readonly '<error URN>': s.<Error brand>Input;
}
```

One property for each error of the manifest. The key is the URN of the error. The value is the input type of the error schema: the plain payload, with `kind`. If the manifest has no errors, the interface is `export interface ErrorPayloads {}`. Then `ErrorUrn` is `never`, and a handler cannot call `fail`.

### `Success`, `Failure` and `Result`

```ts
export interface Success<T> {
  readonly ok: true;
  readonly value: T;
}

export interface Failure<E> {
  readonly ok: false;
  readonly error: E;
}

export type Result<T, E> = Success<T> | Failure<E>;
```

Each handler returns a `Result`: its output, or one of the declared errors of its operation.

### `ErrorUrn` and `ErrorFields`

```ts
export type ErrorUrn = keyof ErrorPayloads;

export type ErrorFields<K extends ErrorUrn> = Omit<ErrorPayloads[K], 'kind'>;
```

`ErrorUrn` is the union of all error URNs of the manifest. `ErrorFields<K>` is the payload of the error `K` without `kind`, as a handler gives it to `fail`.

### `ok`

```ts
export function ok<T>(value: T): Success<T>;
```

Returns `{ ok: true, value }`.

### `fail`

```ts
export function fail<K extends ErrorUrn>(
  kind: K,
  ...fields: {} extends ErrorFields<K> ? [fields?: ErrorFields<K>] : [fields: ErrorFields<K>]
): Failure<ErrorPayloads[K]>;
```

Returns `{ ok: false, error: { ...fields, kind } }`. The fields argument is optional only if the error has no mandatory fields. `fail` does not parse the fields. `executeOperation` parses them.

```ts
fail('urn:demo:shipping:quote:error:too_heavy_for_express', { weight_grams: 6000 })
// {"ok":false,"error":{"weight_grams":6000,"kind":"urn:demo:shipping:quote:error:too_heavy_for_express"}}
```

## Handler contracts

```ts
/** <operation URN> — <description> */
export type <Operation brand>Handler = (
  input: s.<Input entity brand>,
) => Result<s.<Output entity brand>Input, <error types>>;
```

| Part | Type | Description |
| --- | --- | --- |
| `input` | `s.<Input entity brand>` | The parsed, branded input entity |
| Output | `s.<Output entity brand>Input` | The plain output entity, with no brands |
| Error | `s.<Error brand>Input`, one for each declared error | The union of the plain payloads of the declared errors, in the sequence of the `errors` list. `never` if the operation declares no errors |

A handler is synchronous. It returns the `Result`. It does not return a `Promise`. Example from tutorial 2:

```ts
/** urn:demo:shipping:quote:operation:quote_shipping — Calculate the price to send a parcel */
export type QuoteQuoteShippingHandler = (
  input: s.ParcelParcel,
) => Result<s.QuoteQuoteInput, s.QuoteTooHeavyForExpressInput>;
```

## Registry

### `DomainCoreImplementation`

```ts
export interface DomainCoreImplementation {
  readonly '<operation URN>': <Operation brand>Handler;
}
```

One property for each operation of the manifest. The key is the URN of the operation, and the value is its handler type. The core declares itself with `satisfies DomainCoreImplementation`. Gate 1 makes sure of this. Refer to [Verification gates](./verification-gates).

## Dispatch

### `FieldInfo`

```ts
export interface FieldInfo {
  /** The field whose values the property holds; for a link, the linked entity's key field. */
  readonly urn: string;
  readonly primitive: 'boolean' | 'date' | 'decimal' | 'enum' | 'float' | 'integer' | 'string' | 'timestamp';
  readonly required: boolean;
  /** The property holds a list of the field's values. */
  readonly many?: true;
  /** The entity that a link points at, by its key. */
  readonly link?: string;
}
```

A `FieldInfo` describes a property with `ref` to a field, or with `link` to an entity.

| Property | Description |
| --- | --- |
| `urn` | The URN of the field. For a link, the URN of the `key` field of the linked entity |
| `primitive` | The primitive of the field. The union has each primitive that urn-forge knows |
| `required` | `false` if the reference has `required: false` in the manifest. If not, `true` |
| `many` | `true` if the reference has `many` in the manifest. If not, the property is absent. The item count and `unique` are not in `FieldInfo`. They are in the schema |
| `link` | The URN of the linked entity, if the reference is a `link`. If not, the property is absent |

A `FieldInfo` of a list, from a compile of a manifest with `many: { minItems: 1, maxItems: 3, unique: true }`:

```ts
sku: { urn: 'urn:demo:shop:order:field:sku', primitive: 'string', required: true, many: true },
```

The `FieldInfo` of the link `holder` in the insurance domain:

```ts
holder: { urn: 'urn:acme:insurance:customer:field:customer_id', primitive: 'string', required: true, link: 'urn:acme:insurance:customer:entity:customer' },
```

### `EmbeddedInfo`

```ts
export interface EmbeddedInfo {
  readonly entity: string;
  readonly required: boolean;
  readonly many?: true;
  readonly fields: Readonly<Record<string, PropertyInfo>>;
}
```

An `EmbeddedInfo` describes a property with `ref` to an entity. The property holds an embedded object of that entity.

| Property | Description |
| --- | --- |
| `entity` | The URN of the embedded entity |
| `required` | `false` if the reference has `required: false` in the manifest. If not, `true` |
| `many` | `true` if the reference has `many` in the manifest. If not, the property is absent |
| `fields` | One `PropertyInfo` for each property of the embedded entity, keyed by property name, in the sequence of the manifest. An entity that the embedded entity embeds has its own `EmbeddedInfo` here, at each depth |

### `PropertyInfo`

```ts
export type PropertyInfo = FieldInfo | EmbeddedInfo;
```

Only an `EmbeddedInfo` has the key `entity`. Examine this key to know the form of a `PropertyInfo`.

### `InvariantInfo`

```ts
export interface InvariantInfo {
  readonly urn: string;
  readonly rule: unknown;
}
```

| Property | Description |
| --- | --- |
| `urn` | The URN of the invariant |
| `rule` | The rule function of the invariant, `s.<Invariant brand>Rule`, from the schema file. `executeOperation` uses it to find the invariant of an issue |

### `EntityContract`

```ts
export interface EntityContract {
  readonly schema: v.GenericSchema;
  readonly fields: Readonly<Record<string, PropertyInfo>>;
  readonly invariants?: readonly InvariantInfo[];
}
```

| Property | Description |
| --- | --- |
| `schema` | The schema of the entity, from the schema file |
| `fields` | One `PropertyInfo` for each property, keyed by property name, in the sequence of the manifest |
| `invariants` | One `InvariantInfo` for each invariant whose `on` is the entity, in URN order. Then the invariants of each entity that it embeds, at each depth, in the sequence of its properties. Each invariant occurs one time. The property is there only if the list is not empty |

### `ErrorCategory`

```ts
export type ErrorCategory = 'validation' | 'conflict' | 'not_found' | 'forbidden' | 'precondition';
```

### `MessagePart`

```ts
export type MessagePart = { readonly text: string } | { readonly field: string };
```

One part of the message template of an error: literal text, or a `{placeholder}` with the name of a property of the error.

### `ErrorContract`

```ts
export interface ErrorContract extends EntityContract {
  readonly category: ErrorCategory;
  readonly retryable: boolean;
  readonly message: readonly MessagePart[];
}
```

| Property | Description |
| --- | --- |
| `schema` | The schema of the error, from the schema file |
| `fields` | One `PropertyInfo` for each property of the error. The `kind` property is not in this list |
| `invariants` | Never present. An invariant is on an entity, not on an error |
| `category` | The `category` of the error in the manifest |
| `retryable` | The `retryable` value of the error in the manifest |
| `message` | The `message` of the error in the manifest, as a list of parts |

### `OperationContract`

```ts
export interface OperationContract {
  readonly input: EntityContract;
  readonly output: EntityContract;
  readonly errors: Readonly<Record<string, ErrorContract>>;
}
```

`errors` has one `ErrorContract` for each declared error of the operation, keyed by error URN.

### `DispatchMap`

```ts
export const DispatchMap = {
  '<operation URN>': {
    input: { schema: s.<…>Schema, fields: { … }, invariants: [ … ] },
    output: { schema: s.<…>Schema, fields: { … }, invariants: [ … ] },
    errors: { '<error URN>': { schema, category, retryable, message, fields }, … },
  },
} as const satisfies Readonly<Record<keyof DomainCoreImplementation, OperationContract>>;
```

One entry for each operation, keyed by operation URN. If an operation declares no errors, its `errors` is `{}`. The `invariants` of an input or an output are there only if the entity has invariants. Because of `as const`, each value has its literal type. Example from tutorial 2:

```ts
export const DispatchMap = {
  'urn:demo:shipping:quote:operation:quote_shipping': {
    input: {
      schema: s.ParcelParcelSchema,
      fields: {
        weight_grams: { urn: 'urn:demo:shipping:parcel:field:weight_grams', primitive: 'integer', required: true },
        zone: { urn: 'urn:demo:shipping:parcel:field:zone', primitive: 'enum', required: true },
        express: { urn: 'urn:demo:shipping:parcel:field:express', primitive: 'boolean', required: false },
      },
    },
    output: {
      schema: s.QuoteQuoteSchema,
      fields: {
        price_cents: { urn: 'urn:demo:shipping:quote:field:price_cents', primitive: 'integer', required: true },
      },
    },
    errors: {
      'urn:demo:shipping:quote:error:too_heavy_for_express': {
        schema: s.QuoteTooHeavyForExpressSchema,
        category: 'precondition',
        retryable: false,
        message: [{ text: 'An express parcel can weigh 5000 grams at most, not ' }, { field: 'weight_grams' }],
        fields: {
          weight_grams: { urn: 'urn:demo:shipping:parcel:field:weight_grams', primitive: 'integer', required: true },
        },
      },
    },
  },
} as const satisfies Readonly<Record<keyof DomainCoreImplementation, OperationContract>>;
```

The input of `issue_policy` in the insurance domain has a link, `holder`, and a list of embedded entities, `coverages`. It has the two invariants of `policy` and the invariant of the embedded `coverage`:

```ts
    input: {
      schema: s.PolicyPolicySchema,
      fields: {
        policy_id: { urn: 'urn:acme:insurance:policy:field:policy_id', primitive: 'string', required: true },
        holder: { urn: 'urn:acme:insurance:customer:field:customer_id', primitive: 'string', required: true, link: 'urn:acme:insurance:customer:entity:customer' },
        coverages: { entity: 'urn:acme:insurance:policy:entity:coverage', required: true, many: true, fields: {
          peril: { urn: 'urn:acme:insurance:policy:field:peril', primitive: 'enum', required: true },
          limit: { urn: 'urn:acme:insurance:policy:field:limit', primitive: 'decimal', required: true },
          note: { urn: 'urn:acme:insurance:policy:field:note', primitive: 'string', required: false },
        } },
        effective_date: { urn: 'urn:acme:insurance:policy:field:effective_date', primitive: 'date', required: true },
        expiry_date: { urn: 'urn:acme:insurance:policy:field:expiry_date', primitive: 'date', required: true },
        premium: { urn: 'urn:acme:insurance:policy:field:premium', primitive: 'decimal', required: true },
        deductible: { urn: 'urn:acme:insurance:policy:field:deductible', primitive: 'decimal', required: false },
      },
      invariants: [
        { urn: 'urn:acme:insurance:policy:invariant:deductible_below_premium', rule: s.PolicyDeductibleBelowPremiumRule },
        { urn: 'urn:acme:insurance:policy:invariant:term_is_positive', rule: s.PolicyTermIsPositiveRule },
        { urn: 'urn:acme:insurance:policy:invariant:limit_is_positive', rule: s.PolicyLimitIsPositiveRule },
      ],
    },
```

The [Gherkin steps](./gherkin-steps) read `DispatchMap` to find the fields, the primitives and the input invariants of each operation.

## Shell gatekeeper

### `OperationUrn`

```ts
export type OperationUrn = keyof DomainCoreImplementation;
```

The union of all operation URNs of the manifest.

### `BoundaryIssue`

```ts
export interface BoundaryIssue {
  readonly path: string;
  readonly fieldUrn?: string;
  readonly invariantUrn?: string;
  readonly message: string;
}
```

| Property | Description |
| --- | --- |
| `path` | The dot path of the issue in the payload, for example `weight_grams`. For an item of a list, the path has the index of the item, for example `sku.1`. For a property of an embedded entity, the path continues into the object, for example `coverages.1.limit`. An empty string means the payload as a whole |
| `fieldUrn` | The URN of the deepest field on the path. For a link, the URN of the key field. If the path names no field, the property is absent. For example, an issue on the list `coverages` as a whole has no `fieldUrn` |
| `invariantUrn` | The URN of the invariant, if the issue comes from the rule of an invariant of the contract that was parsed. If not, the property is absent |
| `message` | The Valibot message, the `message` of the invariant, or a message of `executeOperation` |

To find `fieldUrn`, `executeOperation` follows the path through the `fields` of the contract and of each `EmbeddedInfo`. It ignores the list indexes.

An issue of an invariant has the path of the first field that the rule names. Thus it has a `fieldUrn` and an `invariantUrn`. The issue of an invariant of an embedded entity has the nested path, for example `coverages.1.limit`. To find the invariant, `executeOperation` compares the `requirement` of the Valibot issue with the `rule` of each `InvariantInfo`.

### `DomainError`

```ts
export type DomainError<U extends OperationUrn = OperationUrn> = U extends OperationUrn
  ? {
      readonly [K in keyof DeclaredErrors<U>]: {
        readonly urn: K;
        readonly category: ErrorCategory;
        readonly retryable: boolean;
        readonly message: string;
        readonly fields: DeclaredErrors<U>[K] extends { readonly schema: infer S extends v.GenericSchema }
          ? v.InferOutput<S>
          : never;
      };
    }[keyof DeclaredErrors<U>]
  : never;
```

A declared error of the operation `U`, after the parse. `DeclaredErrors<U>` is the `errors` entry of `U` in `DispatchMap`. It is not exported. `DomainError<U>` is a union with one member for each declared error, so a `switch` on `urn` gives the correct `fields`. If `U` declares no errors, the type is `never`.

| Property | Description |
| --- | --- |
| `urn` | The URN of the error |
| `category` | The category of the error |
| `retryable` | The `retryable` value of the error |
| `message` | The message template, with the value of the field in each `{placeholder}`. Each value goes through `String(…)` |
| `fields` | The parsed, branded payload of the error, with `kind` |

### `ExecuteResult`

```ts
export type ExecuteResult<U extends OperationUrn = OperationUrn> =
  | { readonly ok: true; readonly urn: U; readonly output: v.InferOutput<(typeof DispatchMap)[U]['output']['schema']> }
  | { readonly ok: false; readonly kind: 'DomainError'; readonly urn: U; readonly error: DomainError<U> }
  | { readonly ok: false; readonly kind: 'UnknownOperation'; readonly urn: string; readonly issues: readonly BoundaryIssue[] }
  | { readonly ok: false; readonly kind: 'InputRejected' | 'ContractViolation'; readonly urn: U; readonly issues: readonly BoundaryIssue[] };
```

The generated file writes each member on more than one line. The members are the same.

| `ok` | `kind` | Other properties | Description |
| --- | --- | --- | --- |
| `true` | None | `urn`, `output` | The operation succeeded. `output` is the parsed, branded output entity |
| `false` | `'DomainError'` | `urn`, `error` | The handler refused with a declared error. This is a correct result |
| `false` | `'UnknownOperation'` | `urn`, `issues` | The URN is not an operation of this domain |
| `false` | `'InputRejected'` | `urn`, `issues` | The caller sent a payload that the input schema refuses. This includes a payload that breaks an invariant of the input entity |
| `false` | `'ContractViolation'` | `urn`, `issues` | The core did not obey its contract. This includes an output that breaks an invariant of the output entity. This shows a bug in the core |

### `executeOperation`

```ts
export function executeOperation<U extends OperationUrn>(
  urn: U,
  rawPayload: unknown,
  core: DomainCoreImplementation,
): ExecuteResult<U>;
export function executeOperation(urn: string, rawPayload: unknown, core: DomainCoreImplementation): ExecuteResult;
```

With a literal operation URN, the first signature applies, and the result type is specific to the operation. With a `string`, the second signature applies.

`executeOperation` does these steps in this sequence. It stops at the first step that gives a result:

| Step | Action | Condition | Result |
| --- | --- | --- | --- |
| 1 | Find the operation in `DispatchMap` | The URN is not a key of `DispatchMap` | `UnknownOperation`, with one issue: `{ path: '', message: 'unknown operation <urn>' }` |
| 2 | Parse `rawPayload` with the input schema | The parse fails | `InputRejected`, with one issue for each Valibot issue. The handler is not called |
| 3 | Find the handler `core[urn]` | It is not a function | `ContractViolation`, with the message `no handler for <urn>` |
| 4 | Call the handler with the parsed, branded input | The return value is not a `Result`: an object with `ok: true` and a `value` key, or with `ok: false` and an `error` key | `ContractViolation`, with the message `the handler for <urn> did not return a Result; return ok(…) or fail(…)` |
| 5a | If `ok` is `false`: find the error by its `kind` in the `errors` of the operation | The operation does not declare the error | `ContractViolation`, with the message `<urn> failed with <kind>, which it does not declare` |
| 5b | Parse the error with the error schema | The parse fails | `ContractViolation`, with one issue for each Valibot issue |
| 5c | Make the domain error | Always | `DomainError`, with `urn`, `category`, `retryable`, the rendered `message` and the parsed `fields` |
| 6a | If `ok` is `true`: parse `value` with the output schema | The parse fails | `ContractViolation`, with one issue for each Valibot issue |
| 6b | Return the output | Always | `{ ok: true, urn, output }` |

- A parse removes the keys that are not properties of the entity. Refer to [The generated schemas](./generated-schemas).
- The issues of steps 1, 3, 4 and 5a have an empty `path` and no `fieldUrn`.
- In steps 2, 5b and 6a, `fieldUrn` comes from the properties of the input, the error or the output, at each depth. In steps 2 and 6a, `invariantUrn` comes from the invariants of the input or the output. These include the invariants of the embedded entities.
- `executeOperation` does not make sure that a link points at an object that exists. The shell does that, with its store.
- `executeOperation` does not catch an exception that the handler throws.

Results from a real run with the core of tutorial 2:

```ts
executeOperation(U, { weight_grams: 800, zone: 'domestic' }, core)
// {"ok":true,"urn":"urn:demo:shipping:quote:operation:quote_shipping","output":{"price_cents":600}}

executeOperation('urn:demo:shipping:quote:operation:nope', {}, core)
// {"ok":false,"kind":"UnknownOperation","urn":"urn:demo:shipping:quote:operation:nope","issues":[{"path":"","message":"unknown operation urn:demo:shipping:quote:operation:nope"}]}

executeOperation(U, { weight_grams: 0 }, core)
// {"ok":false,"kind":"InputRejected","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"weight_grams","fieldUrn":"urn:demo:shipping:parcel:field:weight_grams","message":"Invalid value: Expected >=1 but received 0"},{"path":"zone","fieldUrn":"urn:demo:shipping:parcel:field:zone","message":"Invalid key: Expected \"zone\" but received undefined"}]}

executeOperation(U, null, core)
// {"ok":false,"kind":"InputRejected","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"","message":"Invalid type: Expected Object but received null"}]}

executeOperation(U, { weight_grams: 6000, zone: 'domestic', express: true }, core)
// {"ok":false,"kind":"DomainError","urn":"urn:demo:shipping:quote:operation:quote_shipping","error":{"urn":"urn:demo:shipping:quote:error:too_heavy_for_express","category":"precondition","retryable":false,"message":"An express parcel can weigh 5000 grams at most, not 6000","fields":{"kind":"urn:demo:shipping:quote:error:too_heavy_for_express","weight_grams":6000}}}
```

`U` is `'urn:demo:shipping:quote:operation:quote_shipping'`. These results come from cores that do not obey the contract:

```ts
// The core has no handler for the URN.
// {"ok":false,"kind":"ContractViolation","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"","message":"no handler for urn:demo:shipping:quote:operation:quote_shipping"}]}

// The handler returns 5.
// {"ok":false,"kind":"ContractViolation","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"","message":"the handler for urn:demo:shipping:quote:operation:quote_shipping did not return a Result; return ok(…) or fail(…)"}]}

// The handler fails with an error that the operation does not declare.
// {"ok":false,"kind":"ContractViolation","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"","message":"urn:demo:shipping:quote:operation:quote_shipping failed with urn:x, which it does not declare"}]}

// The handler fails with weight_grams: -1.
// {"ok":false,"kind":"ContractViolation","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"weight_grams","fieldUrn":"urn:demo:shipping:parcel:field:weight_grams","message":"Invalid value: Expected >=1 but received -1"}]}

// The handler returns ok({ price_cents: 1.5 }).
// {"ok":false,"kind":"ContractViolation","urn":"urn:demo:shipping:quote:operation:quote_shipping","issues":[{"path":"price_cents","fieldUrn":"urn:demo:shipping:quote:field:price_cents","message":"Invalid safe integer: Received 1.5"}]}
```

Results from a real run with the core of the insurance domain, where `I` is `'urn:acme:insurance:policy:operation:issue_policy'`. `P` is a valid policy:

```ts
const P = {
  policy_id: '123e4567-e89b-12d3-a456-426614174000',
  holder: '9b2f0c1e-4d3a-4f5b-8c6d-7e8f9a0b1c2d',
  effective_date: '2026-06-01',
  expiry_date: '2026-12-31',
  premium: '120.00',
  coverages: [{ peril: 'fire', limit: '1000.00' }],
};
```

The inputs that follow break these rules, in this sequence:

1. An invariant of `policy`.
2. The invariant of the embedded `coverage`.
3. The `unique` rule of `coverages`.
4. A field of a coverage.
5. The key field of the link `holder`.

Then a changed handler returns an output that breaks an invariant:

```ts
executeOperation(I, { ...P, expiry_date: '2026-05-31' }, core)
// {"ok":false,"kind":"InputRejected","urn":"urn:acme:insurance:policy:operation:issue_policy","issues":[{"path":"expiry_date","fieldUrn":"urn:acme:insurance:policy:field:expiry_date","invariantUrn":"urn:acme:insurance:policy:invariant:term_is_positive","message":"The expiry date must be after the effective date"}]}

executeOperation(I, { ...P, coverages: [{ peril: 'fire', limit: '1' }, { peril: 'flood', limit: '0' }] }, core)
// {"ok":false,"kind":"InputRejected","urn":"urn:acme:insurance:policy:operation:issue_policy","issues":[{"path":"coverages.1.limit","fieldUrn":"urn:acme:insurance:policy:field:limit","invariantUrn":"urn:acme:insurance:policy:invariant:limit_is_positive","message":"The limit of a coverage must be more than 0"}]}

executeOperation(I, { ...P, coverages: [{ peril: 'fire', limit: '1' }, { peril: 'fire', limit: '2' }] }, core)
```

## Declarations that are not exported

The file also declares these items. Other modules cannot import them.

| Name | Description |
| --- | --- |
| `DeclaredErrors<U>` | `(typeof DispatchMap)[U]['errors']` |
| `boundaryIssues(issues, contract)` | Changes Valibot issues to `BoundaryIssue` objects, with the properties and the invariants of the `EntityContract` |
| `isOperationUrn(urn)` | Returns `true` if the URN is a key of `DispatchMap` |
| `isResult(value)` | Returns `true` if the value has the form of a `Result` |
| `renderMessage(parts, fields)` | Puts the field values in the message template |
